# Glossary

Acronyms and project terms used across the per-crate READMEs and persona
docs. Standard industry terms are included for quick reference;
ovstorage-specific terms are here so per-crate docs use the same
vocabulary.

- **ABI** — Application Binary Interface. The binary-level contract (calling convention, struct layout, symbol mangling) that lets a compiled artifact load another at runtime. The C ABI is the only ABI the project treats as stable across Rust versions and toolchains.
- **ADLS** — Azure Data Lake Storage (Gen2). Azure Blob with optional **HNS** (Hierarchical Namespace), which adds POSIX-style directory semantics on top of the flat blob store.
- **authn** — Short for *authentication*. Establishing *who* is calling (a JWT bearer, an mTLS peer cert, a workload identity).
- **authz** — Short for *authorization*. Deciding *whether* an authenticated principal may perform a given operation on a given resource.
- **CAS** — Content-Addressed Storage. Bytes are stored under a key derived from their cryptographic digest, so identical content always shares one on-disk file.
- **FFI** — Foreign Function Interface. The mechanism by which one language calls into compiled code from another (here: C, C++, and Python calling into the Rust core through the C ABI).
- **FUSE** — Filesystem in Userspace. A kernel interface that lets userspace processes implement filesystems; treated as opaque/unsafe for `state_root` because the actual semantics depend on the userspace implementation.
- **HPC** — High-Performance Computing. Multi-node clusters with parallel filesystems (Lustre, GPFS, BeeGFS) where many ranks may launch ovstorage simultaneously against shared storage.
- **IAM** — Identity and Access Management. The cloud-provider subsystem (AWS IAM, Azure RBAC, GCP IAM) that decides which principals may perform which operations on which resources.
- **IMDS** — Instance Metadata Service. The link-local HTTP endpoint (`169.254.169.254` and friends) that cloud VMs use to fetch short-lived workload credentials.
- **JWKS** — JSON Web Key Set. The published set of public keys used to verify JWTs; the broker fetches the configured OIDC provider's JWKS to validate bearer tokens.
- **JWT** — JSON Web Token. The compact, signed token format used for OIDC bearers.
- **LFT** — Large File Transfer. The Omniverse Nucleus bulk-bytes side channel. The Nucleus plugin mints an `LFT redirect` (a presigned PUT/GET URL plus response-parsing instructions) that the host follows directly, keeping the multi-GB payload off the gRPC/WebSocket control channel. The threshold (default 16 MiB) is advertised in the auth handshake's `Auth` envelope as `lft_threshold`.
- **mTLS** — mutual TLS. TLS where both client and server present X.509 certificates. The broker accepts `authn.mode = "mtls"` as a reserved config shape; full certificate validation and principal mapping are not implemented.
- **MSRV** — Minimum Supported Rust Version. The oldest stable Rust toolchain that builds the workspace.
- **OIDC** — OpenID Connect. Identity layer on top of OAuth 2.0; supplies the user/workload identity claims the broker keys policy on.
- **OTel** — OpenTelemetry. Vendor-neutral observability framework (traces, metrics, logs).
- **OTLP** — OpenTelemetry Protocol. The wire format / transport (gRPC or HTTP) that OTel-instrumented processes use to push telemetry to a collector.
- **PKCE** — Proof Key for Code Exchange (RFC 7636). The OAuth 2.0 extension that lets public clients (CLIs, native apps) safely run the authorization-code flow without a client secret.
- **RAII** — Resource Acquisition Is Initialization. C++/Rust idiom where a resource's lifetime is bound to an object's scope; used here for leases and the C++ wrapper.
- **SAS** — Shared Access Signature. Azure's pre-signed-URL equivalent; a query-string token granting time-bounded, scoped access to a blob or container.
- **SPI** — Service Provider Interface. The contract a *provider* (here: a backend plugin) implements so the host (the ovstorage library) can call into it. The dual of "API": where an API is what callers use, an SPI is what implementers fill in.
- **STS** — Security Token Service. AWS's endpoint for exchanging long-lived credentials or workload identities for short-lived session credentials.
- **TCK** — Technology Compatibility Kit. The third-party plugin compatibility kit shipped via `ovstorage-plugin-test` (a controllable test plugin plus runner) that pins SPI behavior so out-of-tree plugin authors can verify conformance.
- **UDS** — Unix-domain socket. Loopback-only IPC primitive on Linux / macOS that supports SCM_CREDENTIALS-style peer-credential lookup; used as a transport for the library↔broker protocol when the broker is per-host. The Windows analog is the named pipe.
- **WAL** — Write-Ahead Logging. SQLite's high-concurrency journaling mode, used by both `index.sqlite` and `auth.sqlite`.
- **WIF** — Workload Identity Federation. Cloud features (AWS IAM Roles Anywhere / web identity, GCP Workload Identity Federation, Azure Federated Credentials) that exchange a workload's existing identity assertion (e.g. a Kubernetes service-account JWT) for cloud credentials, eliminating long-lived secrets.
- **XDG** — The freedesktop.org XDG Base Directory specification, which defines `$XDG_STATE_HOME`, `$XDG_CACHE_HOME`, etc. on Linux. Windows and macOS fall back to platform-native equivalents (`%LOCALAPPDATA%`, `~/Library/...`).

## Project terms

- **Address root** — An absolute `ObjectAddress` prefix a backend currently serves. Static config, direct-mode connections, broker-published roots, and aliases all contribute address roots to the routing table.
- **Alias** — A first-class routing row that rewrites one `ObjectAddress` prefix to another. Aliases resolve once; a second alias hop fails with `AliasChainTooLong`.
- **Auth substrate** — The process-global `(SecretStore, AuthRefreshLock)` pair used for OAuth credential persistence and cross-process refresh serialization. `Library::open(None)` and `LibraryBuilder::open()` initialize it automatically; callers that need a custom auth state directory call `ovstorage::init_auth_substrate(Some(path))` before the first open.
- **Backend** — A configured storage plugin instance. The same plugin binary can produce multiple backends with different buckets, roots, regions, accounts, or credential profiles.
- **StorageBackend** — The plugin-side object-operation SPI trait implemented by one configured backend instance after routing has resolved a caller-facing address.
- **StorageBackendFactory** — The plugin-side factory SPI used by connection management to describe, instantiate, and authenticate a backend kind.
- **AuthzPlugin** — Broker authorization SPI declared in the `ovstorage-authz` crate and implemented by providers such as `ovstorage-authz-toml`. It receives a `Principal`, operation, broker-supplied address, and `policy_epoch`, then returns allow/deny plus an audit-safe explanation. The broker supplies the incoming caller-facing address.
- **Attribution** — The trust-boundary overlay that populates `ObjectInfo.modified_by` with the broker's authn'd principal. The broker stamps `ovstorage-modified-by` into a reserved `user_metadata` key on every mutating call and harvests it back on read; without this overlay every write at the backend would be attributed to the broker's service account, not the human who authenticated to the broker. Configurable via `attribution_strategy` (`user_metadata` / `passthrough` / `external_db`); see `AttributionLayer` in `ovstorage-authz` and the broker-operator docs. Cost is opt-in via `full_metadata` on stat/list.
- **`Body::Stream`** — The streaming variant of the write `Body` enum (`Body::Bytes` / `Body::LocalFile` / `Body::Stream`). Carries chunks chunk-by-chunk through every seam — ingress, dispatcher, plugin SPI, redirect issuer, broker bridge — and is never drained to `Vec<u8>` at the host or plugin (memory-DoS posture on the public REST gateway). In Python and JavaScript bindings it is exposed as an `async for`-driven iterator and a `ReadableStream` respectively.
- **Broker** — Optional `ovstorage-broker` process that holds long-lived credentials, runs broker-core authn plus authz plugins, and may share metadata/cache across clients. It is not required for Direct mode.
- **Brokered mode** — A topology where the library routes through `broker-client` to an `ovstorage-broker`. Backend plugins and long-lived credentials live in the broker; the library follows generic redirects or receives broker-sourced streams.
- **Capability** — A route/backend flag that says which optional behavior callers may rely on, such as native metadata patching, access checks, `watch_directory` streams, or version-list ordering.
- **Conformance harness** — The `ovstorage-plugin-test` crate (the crate name; the design doc that introduced it was titled "plugin-conformance"). A controllable in-tree test plugin plus a runner that exercises the SPI and pins behavior so out-of-tree plugin authors can verify conformance against the same suite (the project's TCK). The plugin's manifest carries `test_only = true` so production hosts refuse to load it unless `LibraryBuilder::allow_test_plugins(true)` was called.
- **Connection** — A configured backend instance created through the `Storage` management API in Direct mode. Broker-side backend instances are configured by the broker's TOML and published to clients as address roots; they are not created through `broker-client` management RPCs.
- **Direct mode** — A topology where the application process links `ovstorage`, loads backend plugins in-process, and coordinates cache/state locally through `state_root` and `cache_root`.
- **ErrorCode** — The closed-set typed-error taxonomy carried in every `ovstorage::Error` and the protobuf/REST/CAPI error envelopes. Variants the docs reference repeatedly: `Transient` (retry — network blip, throttling, transient backend 5xx; library and dispatcher retry idempotent SPI calls), `BrokerUnavailable` (retry — broker is up but unreachable from this client; same retry posture as `Transient`), `ResourceExhausted` (retry with backoff — typically broker-side queue or per-principal limit), `Unsupported` (do not retry — the operation is not implemented on this backend / kind / mode), `InvalidArgument` (do not retry — caller bug), `NotFound` / `AlreadyExists` / `PreconditionFailed` (semantic — caller decides). See § Error model below.
- **Library** — The application-facing handle created by `LibraryBuilder::open()` / `Library::open(None)` (Rust), `Library::init()` (C++), `ovstorage_library_init` (C), or `Library.open()` (Python). Owns a routing table, plugin dispatch, cache, auth-event channel, and aliases. Multiple library handles may exist in one process, but they share the process-global auth substrate and loaded plugin host callbacks.
- **LocalDelegate** — A leased local path returned by `materialize`; while the delegate is alive, cache GC must not remove the file.
- **Nucleus** — Omniverse Nucleus, NVIDIA's collaboration server platform. The `ovstorage-plugin-nucleus` plugin and its supporting transport/auth/discovery/codegen/client crates let `ovstorage` route addresses at a Nucleus server using its native WebSocket transports (SOWS / ConnLib) plus an LFT side channel for bulk bytes.
- **Omniverse Storage Service** — NVIDIA's storage service exposing the Storage API gRPC + REST contract. The `ovstorage-plugin-services-client` plugin routes addresses at a deployed Omniverse Storage Service through tonic-generated clients, using HTTP discovery (`/api/v1/services` + `/api/v1/auth-config`) to bootstrap the gRPC endpoint and an OIDC bearer-token interceptor for auth. Watches use the notifications consumer's `EventConsumerService.ConsumeNonDurableEvents`; ACL checks read the `acl` user-metadata key.
- **ObjectAddress** — The caller-facing URL. Routing canonicalizes only the scheme/host/port/query encoding and preserves object-key bytes.
- **ObjectInfo** — The small metadata record returned by `stat`, reads, writes, lists, directory operations, and metadata patches: canonical address, `kind`, backend-observed facts (`etag` / `version` / `size` / `mtime`), backend-owned system metadata, and caller-owned user metadata.
- **ObjectKind** — The discriminator on `ObjectInfo.kind`: `File` for regular objects; `Directory` for backends with native directory inodes (POSIX `file:`, ADLS Gen2 HNS, Nucleus) where the directory persists independently of contained objects; `DirectoryMarker` for zero-byte marker objects on flat key namespaces (S3 `dir/`, GCS `dir/`) — after `delete_directory` removes the marker, the directory falls to `DirectoryInferred` if children remain, or vanishes entirely if not; `DirectoryInferred` for directories whose existence is implied by at least one descendant key sharing the prefix (no backing storage object; vanishes once the last child is deleted). Helpers: `kind.is_file()`, `kind.is_directory()`.
- **IfDestExists** — The destination-side precondition on `WriteOptions` / `CopyOptions` / `RenameOptions`: `Overwrite` (default) replaces any existing destination; `Fail` refuses the operation if the destination exists (honored by plugins advertising `supports_no_overwrite_write`); `MatchEtag(etag)` refuses unless the destination's current etag matches (honored by plugins advertising `supports_if_match_write`). The companion `if_source: Option<String>` on `CopyOptions` / `RenameOptions` constrains the source by etag.
- **etag** — An opaque string identifying a specific version of an object. Returned on `ObjectInfo.etag` and accepted on `ReadOptions::if_match` / `DeleteOptions::if_match` / `UpdateMetadataOptions::if_match` / `CopyOptions::if_source` / `RenameOptions::if_source` and inside `IfDestExists::MatchEtag(etag)`. The internal structure is the plugin's choice: HTTP-derived backends use the wire `ETag` header value (quoted); the `file` plugin synthesizes `"size:N,mtime:Tms"`; GCS uses the generation number. The host never parses or interprets it.
- **Plugin** — A dynamically loaded `cdylib` that implements one of the project's two SPIs. *Storage plugins* are loaded as `libovstorage_plugin_*` cdylibs exporting `ovstorage_plugin_manifest_v1` + `ovstorage_plugin_init_v1` (e.g. `ovstorage-plugin-file`, `ovstorage-plugin-s3`); *authz plugins* are loaded as `libovstorage_authz_*` cdylibs exporting `ovstorage_authz_plugin_manifest_v1` + `ovstorage_authz_plugin_init_v1` (e.g. `ovstorage-authz-toml`). The two SPIs version independently (`OVSTORAGE_PLUGIN_ABI_VERSION` vs `OVSTORAGE_AUTHZ_PLUGIN_ABI_VERSION`). Direct-mode hosts load storage plugins explicitly with `Library::load_plugin` / `load_plugins_from_dir` (or the C/C++/Python equivalents); passing `None` / `NULL` to the directory loader resolves `OVSTORAGE_PLUGIN_DIR` and the per-binding `default_plugin_dir()` fallback.
- **ReadRedirect / WriteRedirect** — A generic HTTP request plus response-parsing instructions minted by a plugin or broker. The library follows it without knowing which provider produced it.
- **ResolvedTarget** — The post-routing target `(backend_id, resolved_address)` handed to a plugin. Audit and tracing carry both this and the original `ObjectAddress`; broker authz policy is evaluated on the incoming `ObjectAddress`.
- **Route** — A row in the routing table keyed by an absolute `ObjectAddress` prefix. The dispatcher resolves a caller's address by longest-prefix match against the route set; each route names a backend or alias target.
- **Route epoch** (also written `route_epoch` in code and TOML) — A monotonically increasing counter bumped when route resolution can change: config edit, connection update, address-root watch event, alias change, visibility flip, plugin reload, or backend failure.
- **SecretBytes** — A zeroized, redacted secret container. Secrets are not printable, logged, serialized to plaintext disk, or emitted in audit/tracing payloads.
- **Storage trait** — The abstract operation surface declared by `ovstorage` and implemented by `Library`: address-routed object/capability operations plus management, global introspection, and authentication-event APIs. The Rust type vocabulary it speaks in is declared in `ovstorage-plugin`.
- **SystemMetadata** — Backend-owned, read-only metadata that ovstorage shuttles opaquely to the caller (plugin-chosen keys, typically raw vendor headers like `x-amz-storage-class` or `x-ms-lease-state`). Values whose semantics ovstorage understands — content hashes (`ObjectInfo.checksums`) and caller-effective permissions (`ObjectInfo.effective_permissions`) — live in typed fields instead.
- **UserMetadata** — Caller-owned metadata set on write and later edited through `UpdateMetadataOptions.user_metadata_set` / `user_metadata_remove`.
- **Visibility** — Per-address-root listing/resolution posture: `Visible`, `Hidden`, or `Suppressed`. Visibility affects `list_address_roots`; suppression also blocks direct dispatch for that row.
- **`audit_id`** — A per-RPC opaque correlation ID the broker stamps on every gRPC call at request entry (and the library mirrors on its own dispatch path). It threads through tracing spans, error-detail envelopes (`pb::ErrorDetail.audit_id`), redirect envelopes (`ReadRedirect.audit_id` / `WriteRedirect.audit_id`), and authz decisions so a single operation can be reconstructed across components. It carries no signing material and grants no authority — it is purely a stable string for cross-component log correlation.
- **`policy_epoch`** — A monotonically-increasing `u64` carried in every `AuthzRequest`. The broker advances it on each successful policy reload (SIGHUP) and persists the counter under `state_root` so it never repeats across restarts; in-memory mode (no `state_root`) advances the counter past the previous broker's max on each reload to avoid epoch reuse. Cached authz decisions whose recorded epoch is older than the current value are invalidated; freshness modes (`strict` / `grace_window`) decide whether a previously-authorized scope can still be served within a configured window.
- **`struct_size`** — The first field of every public C-ABI options struct (and manifest, init result, vtable). Declared `usize` in the Rust source; emitted as `size_t` in the generated `ovstorage.h` because `usize_is_size_t = true` in `ovstorage-capi/cbindgen.toml`. The callee validates `struct_size >= sizeof(known_minimum)` before reading any tail field, so newer hosts running older callers reject undersized inputs cleanly rather than reading uninitialized memory; older hosts running newer callers accept the larger struct and ignore the unknown tail.
- **state_root** — Durable per-user/per-host state: SQLite WAL files, OAuth handles, leases, staging metadata, and policy snapshots. It must survive cache wipes.
- **cache_root** — Opaque content-addressed object bytes. It is safe to delete, subject to normal lease rules.
- **SecretStorageKind** — The `OsKeyring | Database | External(Arc<dyn SecretStorage>)` selector that picks where the credential cache persists secret material. `OsKeyring` uses the platform keyring; `Database` stores plaintext rows in `auth.sqlite` (intended for sandboxed/test setups); `External` plugs in a caller-supplied store such as Vault or a cloud secret manager. There is no `EncryptedFile` variant today.

## Error model

Stable, categorized, language-neutral. Codes:

**Generic**
- `NotFound`, `AlreadyExists`, `PermissionDenied`, `PreconditionFailed`, `Conflict`, `DirectoryNotEmpty`, `Unsupported`, `InvalidArgument`, `IncompatibleType`, `Locked`, `Cancelled`, `DeadlineExceeded`, `Transient`, `ResourceExhausted`, `IntegrityFailure`, `Internal`.

**Retryability.** The library's idempotent-op retry layer treats `Transient`, `BrokerUnavailable`, `ResourceExhausted`, `DeadlineExceeded`, `CacheLockContention`, and `AuthorizationLeaseExpired` as retryable (per the workspace's pinned `no_retry_on_transient_pinned` policy) and every other variant as terminal. `Cancelled`, `PermissionDenied`, `PreconditionFailed`, `ObjectModified`, `Unsupported`, `InvalidArgument`, `IncompatibleType`, `Locked`, `Conflict`, and `*ConfigField`-style settings errors all surface to the caller without a retry. `BrokerUnavailable` triggers reconnect to the broker before the next attempt; `ResourceExhausted` adds a longer backoff than `Transient` to avoid amplifying rate limits.

**Brokered**
- `BrokerUnavailable`, `BrokerRequired`, `RedirectExpired`, `PolicyEpochStale`, `AuthorizationLeaseExpired`.

**Cache and state**
- `CacheCorrupt`, `StagingExpired`, `CommitAmbiguous`, `CacheLockContention`, `StateRootUnavailable`, `NetworkFilesystemRefused`.

**Preconditions and validation**
- `ObjectModified` — the `if_match` etag (or `if_source` / `IfDestExists::MatchEtag` for copy/rename/write) didn't match what the backend accepted; the bytes differ from the etag the caller captured. A backend-native identity/precondition token that has been rejected or garbage-collected also maps here. A purged or lifecycle-deleted version selected by address surfaces as `NotFound` — there's no separate `VersionNotFound`, since callers rarely need to distinguish "version is gone" from "object is gone". The new response etag is carried structurally on `Error::context` as `ErrorContext::Identity { new_etag: Option<String> }`; consumers read it directly rather than parsing the `message`.

`DirectoryNotEmpty` is the non-recursive directory-delete refusal: a native directory (`ObjectKind::Directory`), or a backend with equivalent semantics, still has children. Flat object stores that only remove marker objects (`ObjectKind::DirectoryMarker`) do not use this code for remaining descendants; once the marker is removed, the operation succeeds and the directory falls to `ObjectKind::DirectoryInferred` if children remain.

**Routing**
- `NoRoute`, `RouteConflict`, `NotConfigured`, `AliasChainTooLong`.

**Credential**
- `CredentialExpired`, `CredentialUnavailable`.

**Authentication (per-connection, distinct from authz `PermissionDenied`)**

`ErrorCode` is a flat C-style enum; the per-variant structured fields below ride on `Error::context` as `ErrorContext::Auth { connection_id, reason, expired_at }`. Plugins populate the variant via `Error::with_context(ErrorContext::Auth { … })`; hosts and applications match on the structured payload rather than parsing the `message`.

- `AuthRequired` — the operation cannot proceed because the connection is not currently authenticated. Distinct from `PermissionDenied` (which means "authenticated, but not allowed"). Applications match on this error to decide whether to call `authenticate_connection` (under `OnDemand` strategy) or wait for the library to auto-trigger (under `OnTouch`). `Error::context` carries `Auth { connection_id, reason: Option<String>, expired_at: None }`.
- `AuthCancelled` — auth was cancelled, either by the application dropping the stream or by the library's deadline. The connection's `auth_state` reflects what came before. `Error::context` carries `Auth { connection_id, reason: Option<String>, expired_at: None }`.
- `AuthExpired` — the connection was authenticated but the token has expired mid-operation; the next `authenticate_connection` call should refresh. `Error::context` carries `Auth { connection_id, reason, expired_at: Some(SystemTime) }`.

**Content**
- `ContentMismatch`, `ContentChecksumMismatch`.

Errors carry a stable `ErrorCode` enum value, a human-readable `message: String`, and an optional typed `context: Option<ErrorContext>` payload (variants `Identity { new_etag }` for `ObjectModified` and `Auth { connection_id, reason, expired_at }` for the auth codes). Wider canonical-context payloads (originating `ObjectAddress`, `ResolvedTarget`, backend name, provider request id) ride on `message`; adding them as a typed payload appends a new `ErrorContext` variant under the same banded mechanism. The error-mapping layer **redacts secret-shaped fields** (anything `SecretBytes`-typed, presigned-URL query strings, broker-issued tokens) before constructing the public `Error` value: presigned redirects appear in audit and tracing as their canonicalized request-line minus query-string, never as the signed URL itself, and OAuth refresh tokens are referenced by hash only.

The C ABI surface is `ffi::Error { code: ErrorCode, message_ptr: *mut c_char, message_len: usize, context: *mut ErrorContextV1 }` — public fields the host reads directly. The `context` pointer is NULL when the error has no structured payload; otherwise it points at a heap-owned tagged-union (`ErrorContextKindV1::Identity` / `Auth`) freed alongside the message buffer in `ovstorage_plugin_error_free`. Hosts that lift the context out of the parent error own the pointer and must call `ovstorage_plugin_error_context_free` exactly once. Dedicated accessor functions (`ovstorage_error_code()` / `ovstorage_error_message()`) are not yet emitted.
