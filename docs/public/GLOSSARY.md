# Glossary

Acronyms and project terms used across the per-crate READMEs and persona
docs. Standard industry terms are included for quick reference;
ovstorage-specific terms are here so per-crate docs use the same
vocabulary.

Where an entry says "ABI-v2", that is the plugin ABI family — a version
space of its own, at 13 in 0.2.1 with a floor of 5 — and never the
ovstorage package version.

- **ABI** — Application Binary Interface. The binary-level contract (calling convention, struct layout, symbol mangling) that lets a compiled artifact load another at runtime. The C ABI is the only ABI the project treats as stable across Rust versions and toolchains.
- **ADLS** — Azure Data Lake Storage (Gen2). Azure Blob with optional **HNS** (Hierarchical Namespace), which adds POSIX-style directory semantics on top of the flat blob store.
- **authn** — Short for *authentication*. Establishing *who* is calling (a JWT bearer, an mTLS peer cert, a workload identity).
- **authz** — Short for *authorization*. Deciding *whether* an authenticated principal may perform a given operation on a given resource.
- **CAS** — Content-Addressed Storage. Bytes are stored under a key derived from their cryptographic digest, so identical content always shares one on-disk file.
- **FFI** — Foreign Function Interface. The mechanism by which one language calls into compiled code from another (here: C, C++, and Python calling into the Rust core through the C ABI).
- **FUSE** — Filesystem in Userspace. A kernel interface that lets userspace processes implement filesystems; treated as opaque/unsafe for `state_root` because the actual semantics depend on the userspace implementation.
- **HPC** — High-Performance Computing. Multi-node clusters with parallel filesystems (Lustre, GPFS, BeeGFS) where many ranks may launch ovstorage simultaneously against shared storage.
- **IAM** — Identity and Access Management. The cloud-provider subsystem (AWS IAM, Azure RBAC, GCP IAM) that decides which principals may perform which operations on which resources.
- **IMDS** — Instance Metadata Service. The link-local HTTP endpoint (`169.254.169.254` and friends) that cloud VMs use to fetch short-lived workload credentials.
- **JWKS** — JSON Web Key Set. The published set of public keys for verifying JWTs; the broker fetches the configured OIDC provider's JWKS to validate bearer tokens.
- **JWT** — JSON Web Token. The compact, signed token format used for OIDC bearers.
- **LFT** — Large File Transfer. The Omniverse Nucleus bulk-bytes side channel. The Nucleus plugin mints an `LFT redirect` (a presigned PUT/GET URL plus response-parsing instructions) that the host follows directly, keeping the multi-GB payload off the gRPC/WebSocket control channel. The threshold (default 16 MiB) is advertised in the auth handshake's `Auth` envelope as `lft_threshold`.
- **mTLS** — mutual TLS. TLS where both client and server present X.509 certificates. The broker's `authn_mode = "mtls"` verifies client certificates against `listener.tls.client_ca_path` and identifies the caller by the verified leaf certificate's SHA-256 fingerprint.
- **MSRV** — Minimum Supported Rust Version. The oldest stable Rust toolchain that builds the workspace.
- **OIDC** — OpenID Connect. Identity layer on top of OAuth 2.0; supplies the user/workload identity claims the broker keys policy on.
- **OTel** — OpenTelemetry. Vendor-neutral observability framework (traces, metrics, logs).
- **OTLP** — OpenTelemetry Protocol. The wire format / transport (gRPC or HTTP) that OTel-instrumented processes use to push telemetry to a collector.
- **PKCE** — Proof Key for Code Exchange (RFC 7636). The OAuth 2.0 extension that lets public clients (CLIs, native apps) safely run the authorization-code flow without a client secret.
- **RAII** — Resource Acquisition Is Initialization. C++/Rust idiom where a resource's lifetime is bound to an object's scope; used here for leases and the C++ wrapper.
- **SAS** — Shared Access Signature. Azure's pre-signed-URL equivalent; a query-string token granting time-bounded, scoped access to a blob or container.
- **STS** — Security Token Service. AWS's endpoint for exchanging long-lived credentials or workload identities for short-lived session credentials.
- **TCK** — Technology Compatibility Kit. The third-party plugin compatibility kit shipped via `ovstorage-plugin-test` (a controllable test plugin plus runner) that pins the Layer ABI behavior so out-of-tree plugin authors can verify conformance.
- **UDS** — Unix-domain socket. Loopback-only IPC primitive on Linux / macOS that supports SCM_CREDENTIALS-style peer-credential lookup; used as a transport for the library↔broker protocol when the broker is per-host. The Windows analog is the named pipe.
- **WAL** — Write-Ahead Logging. SQLite's high-concurrency journaling mode, used by both `index.sqlite` and `auth.sqlite`.
- **WIF** — Workload Identity Federation. Cloud features (AWS IAM Roles Anywhere / web identity, GCP Workload Identity Federation, Azure Federated Credentials) that exchange a workload's existing identity assertion (e.g. a Kubernetes service-account JWT) for cloud credentials, eliminating long-lived secrets.
- **XDG** — The freedesktop.org XDG Base Directory specification, which defines `$XDG_STATE_HOME`, `$XDG_CACHE_HOME`, etc. on Linux. Windows and macOS fall back to platform-native equivalents (`%LOCALAPPDATA%`, `~/Library/...`).

## Project terms

- **Address root** — An absolute `ObjectAddress` prefix a backend currently serves. Direct-mode connections, broker-published roots, and aliases contribute roots consumed by router Layers.
- **Alias** — A routing rule that rewrites one `ObjectAddress` prefix to another, applied per hop by the `AliasWrapper`. Resolution follows a chain of rules (longest-prefix match per hop), bounded by an eight-hop cap and cycle detection; exceeding the cap or revisiting an address fails with `AliasChainTooLong`.
- **Auth substrate** — The process-global `(SecretStore, AuthRefreshLock)` pair used for OAuth credential persistence and cross-process refresh serialization. Rust hosts call `ovstorage::init_auth_substrate` before loading plugins; binding hosts initialize it as part of stack construction.
- **Backend** — A leaf `Layer` that serves object addresses, produced by a `BackendFactory`. The same plugin kind can produce multiple configured instances for different buckets, roots, regions, accounts, or credential profiles. See the top-level `README.md` §1 for how a backend sits at the bottom of a `Stack`.
- **BackendFactory** — The ABI-v2 factory that describes and constructs backend Layers; hosts reach it through the plugin `create_backend` vtable slot.
- **Authorization Layer** — The broker and REST gateway's outermost auth wrapper. `builtin-auth` authenticates the transport principal, evaluates the TOML policy against the incoming caller-facing address, and stamps the principal identity into allowed requests; a loaded wrapper marked `auth_capable` may provide that contract instead.
- **Attribution** — The trust-boundary overlay that populates `ObjectInfo.modified_by` with the broker's authn'd principal. The broker stamps `ovstorage-modified-by` into a reserved `user_metadata` key on every mutating call that carries caller metadata — `write`, `write_stream`, `write_redirect` and `update_metadata` — and harvests it back on read. `continue_write` carries no metadata to stamp and its commit applies a copy that travelled out to the client, so under `user_metadata` the overlay stamps the principal on the reported result itself, and asserts it on the request's extensions for the plugin to write where the backend records metadata at the finalize rather than when the redirect was minted. `copy`, `rename` and `create_directory` carry no `user_metadata` in their options, so the overlay stamps none of them — it harvests the results of `copy` and `create_directory`, while `rename` returns nothing to harvest and passes straight through; without this overlay a backend that records a writer at all records the broker's service account rather than the human who authenticated to it, and a backend that records none — S3, GCS, Azure — leaves `modified_by` empty. Both remote hosts compose it **below the router, one instance per branch** — or, in a graph with no router, directly above its single backend — and only where the backend's kind declares it can carry that key (`supports_user_metadata` on the kind descriptor), so a kind declaring `false` is handed no host-generated stamp and a kind that declares nothing gets no overlay. The declaration is per kind, so a kind declaring `true` may still have roots that cannot store the key, and what such a root does with the stamp is that plugin's behaviour — the in-tree case is `omniverse-storage-service`, whose row in the broker-operator guide's per-kind table records what it does. A copy the backend declines (emulated by `copy_rename_fallback`, which fabricates its write below that wrapper) is still attributed. Configurable via `attribution_strategy`, which is process-wide: branches differ by whether they declare the layer, not by how it behaves. `user_metadata` stamps and harvests; `passthrough` makes the layer a no-op so an upstream broker's stamp survives a chain — for a redirect write that means the deeper broker applies whatever the continuation carried, which is a copy the client held; `external_db` is reserved for a future strategy and a host given it refuses to start. See `AttributionLayer` in `ovstorage-authz` and the broker-operator docs. Harvesting a broker-attested stamp costs nothing extra on stat/list; it is a plugin's *native* `modified_by` that is gated behind `full_metadata`, because populating it can mean an extra OS call or round-trip.
- **`Body::Stream`** — The streaming variant of the write `Body` enum (`Body::Bytes` / `Body::LocalFile` / `Body::Stream`). The public REST gateway carries it chunk-by-chunk through the Layer and plugin seams without whole-body buffering. The gRPC broker coalesces uploads at or below its bounded threshold into replayable `Body::Bytes` after authentication and preserves larger uploads as bounded streams. In Python and JavaScript bindings it is exposed as an `async for`-driven iterator and a `ReadableStream` respectively.
- **Broker** — Optional `ovstorage-broker` process that holds long-lived credentials, runs a selected built-in or auth-capable plugin listener-auth wrapper, and may share metadata/cache across clients. It is not required for Direct mode.
- **Brokered mode** — A topology where the library routes through `broker-client` to an `ovstorage-broker`. Backend plugins and long-lived credentials live in the broker; the library follows generic redirects or receives broker-sourced streams.
- **Capability** — A route/backend flag that says which optional behavior callers may rely on, such as native metadata patching, access checks, `watch_directory` streams, or version-list ordering.
- **Conformance harness** — The `ovstorage-plugin-test` crate (the crate name; the design doc that introduced it was titled "plugin-conformance"). A controllable test plugin plus runner that pins ABI-v2 Layer behavior for out-of-tree plugin authors. Its manifest is `test_only`, so production hosts reject it unless plugin loading explicitly allows test plugins.
- **Connection** — Backend configuration and credentials attached to a named backend Layer. Stack configuration applies connections during build; runtime management uses the Layer connection-lifecycle slots where supported.
- **Direct mode** — A topology where the application process links `ovstorage`, loads backend plugins in-process, and coordinates cache/state locally through `state_root` and `cache_root`.
- **ErrorCode** — The closed-set typed-error taxonomy carried in every `ovstorage::Error` and the protobuf/REST/CAPI error envelopes. Variants the docs reference repeatedly: `Transient` (retryable by an explicitly composed retry Layer), `BrokerUnavailable` (retry — broker is up but unreachable from this client), `ResourceExhausted` (retry with backoff — typically broker-side queue or per-principal limit), `Unsupported` (do not retry — the operation is not implemented on this backend / kind / mode), `InvalidArgument` (do not retry — caller bug), `NotFound` / `AlreadyExists` / `PreconditionFailed` (semantic — caller decides). See § Error model below.
- **Layer** — The single operational interface implemented by backends, routers, wrappers, and built Stacks. It carries typed request envelopes, introspection, connection lifecycle, object operations, and authentication events. It is the core contract of the specification described in the top-level `README.md` §1.
- **Stack** — An immutable Layer graph produced by `StackBuilder` (Rust), `Stack` (C++/Python), or the C stack builder. It canonicalizes addresses at entry and delegates to its configured root Layer. See the top-level `README.md` §1 for the composition contract.
- **LocalDelegate** — A leased local path returned by `materialize`; while the delegate is alive, cache GC must not remove the file.
- **Nucleus** — Omniverse Nucleus, NVIDIA's collaboration server platform. The `ovstorage-plugin-nucleus` plugin and its supporting transport/auth/discovery/codegen/client crates let `ovstorage` route addresses at a Nucleus server using its native WebSocket transports (SOWS / ConnLib) plus an LFT side channel for bulk bytes.
- **Omniverse Storage Service** — NVIDIA's storage service exposing the Storage API gRPC + REST contract. The `ovstorage-plugin-services-client` plugin routes addresses at a deployed Omniverse Storage Service through tonic-generated clients, using HTTP discovery (`/api/v1/services` + `/api/v1/auth-config`) to bootstrap the gRPC endpoint and an OIDC bearer-token interceptor for auth. Watches use the notifications consumer's `EventConsumerService.ConsumeNonDurableEvents`; ACL checks read the `acl` user-metadata key.
- **ObjectAddress** — The caller-facing URL, and the name of a *node*. Canonicalization normalizes the scheme, host, port and query encoding, and normalizes the path: escapes are decoded, runs of `/` collapsed, dot segments resolved, the fragment dropped, and the result re-encoded once. The trailing slash is never added or removed — `x` and `x/` name one node, and every site that compares two addresses knows that, but on a flat store they may be two objects, so the caller's spelling reaches the backend. A key that cannot be named by a URI path (a dot segment, a doubled separator, a literal `/` inside a segment) is unaddressable and is omitted from listings rather than mis-addressed.
- **ObjectInfo** — The small metadata record returned by `stat`, reads, writes, lists, directory operations, and metadata patches: canonical address, `kind`, backend-observed facts (`etag` / `version` / `size` / `mtime`), backend-owned system metadata, and caller-owned user metadata.
- **ObjectKind** — The discriminator on `ObjectInfo.kind`: `File` for regular objects; `Directory` for backends with native directory inodes (POSIX `file:`, ADLS Gen2 HNS, Nucleus) where the directory persists independently of contained objects; `DirectoryMarker` for zero-byte marker objects on flat key namespaces (S3 `dir/`, GCS `dir/`) — after `delete_directory` removes the marker, the directory falls to `DirectoryInferred` if children remain, or vanishes entirely if not; `DirectoryInferred` for directories whose existence is implied by at least one descendant key sharing the prefix (no backing storage object; vanishes once the last child is deleted). Helpers: `kind.is_file()`, `kind.is_directory()`.
- **IfDestExists** — The destination-side precondition on `WriteOptions` / `CopyOptions` / `RenameOptions`: `Overwrite` (default) replaces any existing destination; `Fail` refuses the operation if the destination exists (honored by plugins advertising `supports_no_overwrite_write`); `MatchEtag(etag)` refuses unless the destination's current etag matches (honored by plugins advertising `supports_if_match_write`). The companion `if_source: Option<String>` on `CopyOptions` / `RenameOptions` constrains the source by etag.
- **etag** — An opaque string identifying a specific version of an object. Returned on `ObjectInfo.etag` and accepted on `ReadOptions::if_match` / `DeleteOptions::if_match` / `UpdateMetadataOptions::if_match` / `CopyOptions::if_source` / `RenameOptions::if_source` and inside `IfDestExists::MatchEtag(etag)`. The internal structure is the plugin's choice: HTTP-derived backends use the wire `ETag` header value (quoted); the built-in `file` backend synthesizes `"size:N,mtime:Tms"`; GCS uses the generation number. The host never parses or interprets it.
- **Plugin** — A dynamically loaded `cdylib` that implements the storage Layer ABI and advertises backend, wrapper, or router kinds. Direct-mode hosts load trusted plugin paths into a registry before building a Stack. See the top-level `README.md` §1 for the Plugin contract.
- **Plugin init** — The `ovstorage_plugin_init_v1` entry point a host calls after manifest validation. It receives the host callbacks, creates plugin-scoped state, and returns the factory vtable (`create_backend` / `create_wrapper` / `create_router`) plus the kind descriptors the cdylib ships. Individual Layer instances are built later, one per Stack entry, through those factories.
- **Plugin manifest** — The static `ovstorage_plugin_manifest_v1` struct a plugin exports, owned by the cdylib for its lifetime. It carries `struct_size`, the single implemented `abi_version`, `name`, `version`, and the `test_only` marker; the host reads it to accept or reject the plugin (exact ABI-version match, test-plugin gate) before calling **Plugin init**.
- **ReadRedirect / WriteRedirect** — A generic HTTP request plus response-parsing instructions minted by a plugin or broker. The library follows it without knowing which provider produced it.
- **ResolvedTarget** — The post-routing target `(backend_id, resolved_address)` handed to a plugin. Audit and tracing carry both this and the original `ObjectAddress`; broker authz policy is evaluated on the incoming `ObjectAddress`.
- **Route** — A router Layer's mapping from a canonical address-root prefix to a child Layer. Matching is segment-aware and longest-prefix-first.
- **`RootInfoChange`** — The update-stream event through which a router propagates route-table changes, such as an address-root prefix rebinding to a different backend on a config reload. There is no monotonic route-epoch counter. Byte-cache keys are validator-based, formed from the canonical address prefix plus the object's etag/version; route identity is deliberately excluded from the key.
- **SecretBytes** — A zeroized, redacted secret container. Secrets are not printable, logged, serialized to plaintext disk, or emitted in audit/tracing payloads.
- **SystemMetadata** — Backend-owned, read-only metadata that ovstorage shuttles opaquely to the caller (plugin-chosen keys, typically raw vendor headers like `x-amz-storage-class` or `x-ms-lease-state`). Values whose semantics ovstorage understands — content hashes (`ObjectInfo.checksums`) and caller-effective permissions (`ObjectInfo.effective_permissions`) — live in typed fields instead.
- **UserMetadata** — Caller-owned metadata set on write and later edited through `UpdateMetadataOptions.user_metadata_set` / `user_metadata_remove`.
- **Visibility** — Per-address-root listing/resolution posture: `Visible`, `Hidden`, or `Suppressed`. Visibility affects `list_address_roots`; suppression also blocks direct dispatch for that row.
- **`audit_id`** — A per-RPC opaque correlation ID the broker stamps on every gRPC call at request entry (and the library mirrors on its own dispatch path). It threads through tracing spans, error-detail envelopes (`pb::ErrorDetail.audit_id`), redirect envelopes (`ReadRedirect.audit_id` / `WriteRedirect.audit_id`), and authz decisions so a single operation can be reconstructed across components. It carries no signing material and grants no authority — it is purely a stable string for cross-component log correlation.
- **`policy_epoch`** — A `u64` field present on the wire (redirect envelopes, error details) that the broker never advances: it maintains no such counter. A policy reload rebuilds the auth layer, and the next request is evaluated against the live policy. `PolicyEpochStale` is a wire error code the broker never raises, so a client waiting on epoch advancement or on that error waits forever.
- **`struct_size`** — The leading field on the `ovstorage_plugin.h` structs a caller declares and passes as a unit: every per-operation `*Options` and `*Request`, the plugin manifest and init result, both vtables, `HostCallbacks`, and the kind descriptors — 44 of the header's 189 structs. The other 145 do not carry it: value types (`OvStoragePlugin_Str`, `OvStoragePlugin_Bytes`), result and tagged-union types (`OvStoragePlugin_Capabilities`, `OvStoragePlugin_Connection`, `OvStoragePlugin_ObjectInfo`, `OvStoragePlugin_Error`) are only ever reached through a struct that does, so the outer `struct_size` already bounds them. Declared `usize` in the Rust source and spelled `size_t` in the generated header because `usize_is_size_t = true` in `ovstorage-plugin/cbindgen.toml`. The callee validates `struct_size >= sizeof(known_minimum)` before reading any tail field, so newer hosts running older plugins reject undersized inputs cleanly rather than reading uninitialized memory; older hosts running newer plugins accept the larger struct and ignore the unknown tail. It exists because a plugin is a prebuilt cdylib `dlopen`'d at runtime — a real binary boundary. The application C API in `ovstorage.h` has no such field anywhere: it ships as source compiled together with its implementation, so there is no version skew to detect.
- **state_root** — Durable per-user/per-host state: SQLite WAL files, OAuth handles, leases, staging metadata, and policy snapshots. It must survive cache wipes.
- **cache_root** — Opaque content-addressed object bytes. It is safe to delete, subject to normal lease rules.
- **SecretStore** — The durable credential substrate, keyed by `(backend_kind, connection_id, field)` — the plugin ABI's own composite key. This is where credential bytes actually go in a Rust host, by two routes: `OAuthCredentialProvider` writes here directly and records a `secret_handle` in `auth.sqlite`'s `credential_records`, which holds metadata and never the bytes; and the plugin `secret_get` / `secret_put` / `secret_delete` host callbacks are backed by it, which is how a loaded plugin persists a refresh token. It is a trait with one shipping implementation, `SqliteSecretStore`, which keeps the bytes in a `secrets` table in `auth.sqlite`. The auth directory is created `0700` and the database `0600`, with an owner-only DACL on Windows; that file permission is the whole of the protection against another OS user on the same machine, and it is the reason the bytes may sit on disk in the clear. Earlier releases put them in an OS keyring instead. That was a real secret store on only two of four host substrates — on Linux it resolved to kernel keyutils, whose per-user quota capped a user at roughly five to nine connections, and the standalone C host had no store at all — and because the store was per-machine while the auth directory was per-process, whether a later process found a credential depended on which of the two writers stored it.
- **CredentialCacheDurability** — A selector belonging to the Python binding: an integer-valued class with `PERSISTENT = 0` and `IN_MEMORY_ONLY = 1`, passed as the `Stack(credential_cache_durability=...)` argument. The binding builds a process-local credential cache, so `PERSISTENT` has nothing behind it and `Stack.build()` rejects it explicitly rather than falling back; omission is read as `IN_MEMORY_ONLY`. The selector exists only in the binding: `ovstorage::auth` exports no durability type, and `CredentialCache::new` takes no durability argument. Where credential bytes go in a Rust host is described under **SecretStore**.

## Error model

Stable, categorized, language-neutral. Codes:

**Generic**
- `NotFound`, `AlreadyExists`, `PermissionDenied`, `PreconditionFailed`, `Conflict`, `DirectoryNotEmpty`, `Unsupported`, `InvalidArgument`, `IncompatibleType`, `Locked`, `Cancelled`, `DeadlineExceeded`, `Transient`, `ResourceExhausted`, `IntegrityFailure`, `Internal`.

**Retryability.** The library's idempotent-op retry layer treats `Transient`, `BrokerUnavailable`, `ResourceExhausted`, `DeadlineExceeded`, `CacheLockContention`, and `AuthorizationLeaseExpired` as retryable (per the workspace's pinned `no_retry_on_transient_pinned` policy) and every other variant as terminal. `Cancelled`, `PermissionDenied`, `PreconditionFailed`, `ObjectModified`, `Unsupported`, `InvalidArgument`, `IncompatibleType`, `Locked`, `Conflict`, and `*ConfigField`-style settings errors all surface to the caller without a retry. `BrokerUnavailable` triggers reconnect to the broker before the next attempt. Backoff itself comes from the shared `RetryConfig` and does not vary by code — `ResourceExhausted` and `Transient` wait the same; the code changes only the metrics labels.

**Brokered**
- `BrokerUnavailable`, `BrokerRequired`, `RedirectExpired`, `PolicyEpochStale`, `AuthorizationLeaseExpired`.

**Cache and state**
- `CacheCorrupt`, `StagingExpired`, `CommitAmbiguous`, `CacheLockContention`, `StateRootUnavailable`, `NetworkFilesystemRefused`.

**Partial completion**
- `PartialCompletion` — a compound operation committed one stage durably and then failed a later one, so the caller's state is neither "it happened" nor "it did not". It is never retryable: replaying the operation would re-commit the stage that already landed. What completed, what failed, whether the failed stage is known not to have applied, and what undoing the committed stage would do are carried structurally on `Error::context` as `ErrorContext::Partial { completed, failed, failed_outcome, rollback }`, so one code serves every compound operation rather than growing a code apiece. `rollback` states what undoing the committed stage would COST, not a prohibition — the caller still decides. A user-metadata patch that failed after the bytes committed reports `DestroysRequestedWork`, because undoing the write destroys the object the caller asked for; the design's other case, a rename emulated as copy-then-delete whose delete failed, would report `RestoresPriorState`, because what survives is a duplicate the caller never asked to keep. That second case is the vocabulary's design target and has **no in-tree producer in 0.2.1** — the emulated rename reports `CommitAmbiguous` instead. Distinct from `CommitAmbiguous`, which says the outcome of a *single* commit is unknown rather than that a known stage succeeded and a known later one did not.

**Preconditions and validation**
- `ObjectModified` — the object changed *during* an operation that had already started: a read whose bytes moved under it, or a transfer whose source was replaced after the bytes were staged. A precondition that fails before any work happens is `PreconditionFailed` instead, since nothing was committed. A backend-native identity/precondition token that has been rejected or garbage-collected also maps here. A purged or lifecycle-deleted version selected by address surfaces as `NotFound` — there's no separate `VersionNotFound`, since callers rarely need to distinguish "version is gone" from "object is gone". The new response etag is carried structurally on `Error::context` as `ErrorContext::Identity { new_etag: Option<String> }`; consumers read it directly rather than parsing the `message`. `PreconditionFailed` carries the same payload for the same reason, so a conditional-retry loop reads `new_etag` without first branching on which of the two codes it got.

`DirectoryNotEmpty` is the refusal an operation gives when it would have to empty a directory it was not asked to empty. A native directory (`ObjectKind::Directory`), or a backend with equivalent semantics, still has children: a non-recursive `delete_directory` on that directory refuses, and a `rename` that would replace that directory with another directory can refuse the same way. The `rename` case is narrower than it looks: a destination precondition (`IfDestExists::Fail`) is `AlreadyExists` instead, a platform that raises `EEXIST` rather than `ENOTEMPTY` gives `AlreadyExists` too, and renaming an *object* onto a directory is a different refusal that does not use this code. It sits in the `Precondition` bucket, so it is not retryable — replaying the call cannot empty the directory. Flat object stores that only remove marker objects (`ObjectKind::DirectoryMarker`) do not use this code for remaining descendants; once the marker is removed, the operation succeeds and the directory falls to `ObjectKind::DirectoryInferred` if children remain.

**Routing**
- `NoRoute`, `RouteConflict`, `NotConfigured`, `AliasChainTooLong`.

**Credential**
- `CredentialExpired`, `CredentialUnavailable`.

**Authentication (per-connection, distinct from authz `PermissionDenied`)**

`ErrorCode` is a flat C-style enum; the per-variant structured fields below ride on `Error::context` as `ErrorContext::Auth { connection_id, reason, expired_at }`. Plugins populate the variant via `Error::with_context(ErrorContext::Auth { … })`; hosts and applications match on the structured payload rather than parsing the `message`.

- `AuthRequired` — the operation cannot proceed because the connection is not currently authenticated. Distinct from `PermissionDenied` (which means "authenticated, but not allowed"). Applications match on this error to decide whether to call `authenticate_connection` (under `OnDemand` strategy) or wait for the library to auto-trigger (under `OnTouch`). `Error::context` carries `Auth { connection_id, reason: Option<String>, expired_at: None }`.
- `AuthCancelled` — auth was cancelled, either by the application dropping the stream or by the library's deadline. The connection's `auth_state` reflects what came before. `Error::context` carries `Auth { connection_id, reason: Option<String>, expired_at: None }`.
- `AuthExpired` — the connection was authenticated but the token has expired mid-operation; the next `authenticate_connection` call should refresh. `Error::context` carries `Auth { connection_id, reason, expired_at: Some(SystemTime) }`.

**Content**
- `ContentMismatch`, `ContentChecksumMismatch`.

Errors carry a stable `ErrorCode` enum value, a human-readable `message: String`, and an optional typed `context: Option<ErrorContext>` payload (variants `Identity { new_etag }` for `ObjectModified` and `PreconditionFailed`, `Auth { connection_id, reason, expired_at }` for the auth codes, and `Partial { completed, failed, failed_outcome, rollback }` for `PartialCompletion`). Wider canonical-context payloads (originating `ObjectAddress`, `ResolvedTarget`, backend name, provider request id) ride on `message`; adding them as a typed payload appends a new `ErrorContext` variant under the same banded mechanism. The error-mapping layer **redacts secret-shaped fields** (anything `SecretBytes`-typed, presigned-URL query strings, broker-issued tokens) before constructing the public `Error` value: presigned redirects appear in audit and tracing as their canonicalized request-line minus query-string, never as the signed URL itself, and OAuth refresh tokens are referenced by hash only.

The C ABI surface is `ffi::Error { code: ErrorCode, message_ptr: *mut c_char, message_len: usize, context: *mut ErrorContextV1, next_action: Optional<Str> }` — public fields the host reads directly. The `context` pointer is NULL when the error has no structured payload; otherwise it points at a heap-owned tagged-union (`ErrorContextKindV1::Identity` / `Auth` / `Partial`) freed alongside the message buffer in `ovstorage_plugin_error_free`. Hosts that lift the context out of the parent error own the pointer and must call `ovstorage_plugin_error_context_free` exactly once. 0.2.1 emits no dedicated accessor functions for these (`ovstorage_error_code()` / `ovstorage_error_message()`); read the public fields directly.
