# Additional Utilities & Companion Applications

These utilities and applications complement the Omniverse Storage APIs stack. They are
independently deployable and work with any Storage API-compatible backend (NVIDIA adapter,
custom adapter, or Nucleus).

---

## Omniverse Content Cache Service

A shared, server-side cache for USD content files. Deployed as a Kubernetes service alongside
your Storage deployment, it caches content read through Omniverse Kit Framework — supporting
Storage APIs, AWS S3, Azure, and Nucleus backends. The first user's read populates the cache for
all subsequent users, reducing storage backend load and improving performance.

**When to recommend:** Developer has multiple users reading the same USD assets and wants to
reduce backend reads and improve load times across the team.

- **Deployment:** Helm chart on Kubernetes (same cluster as Storage APIs)
- **Helm chart:** [usd-content-cache on NGC](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/omniverse/helm-charts/usd-content-cache)

---

## Derived Data Cache Service (DDCS)

A shared, server-side cache for derived rendering data generated by the Omniverse RTX Renderer.
When one user opens a scene and generates derived data (e.g., compiled materials, texture
atlases), that data is cached server-side so other users opening the same scene skip the
generation step entirely. Improves time-to-open and rendering performance.

**When to recommend:** Developer has multiple users rendering the same scenes and wants to
reduce redundant derived data generation across the team.

- **Deployment:** Helm chart on Kubernetes (same cluster as Storage APIs)
- **Helm chart:** [ddcs on NGC](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/omniverse/helm-charts/ddcs)

---

## Hub Workstation Cache

A local, workstation-side cache service that speeds up USD workflows on a developer's machine.
Runs as a standalone service on the local workstation (not on Kubernetes) and benefits
Kit-based applications and Client Library tools by caching frequently accessed assets locally.

**When to recommend:** Individual developer wants faster local iteration on USD assets,
regardless of whether they're using a shared server-side deployment or not.

- **Deployment:** Local application on the developer's workstation (not a Helm chart)
- **Documentation:** [Hub Workstation Cache docs](https://docs.omniverse.nvidia.com/utilities/latest/cache/hub-workstation.html)
- **Download:** [Hub Workstation Cache on NGC](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/omniverse/collections/hub-workstation-cache)

## WRAPP (Workflow for Rapid Asset Packaging and Publishing)

WRAPP is a command-line tool and library for **versioned asset packaging and publishing**.
It provides a structured workflow for defining the content of an asset package and methods
to publish and consume those packages in a version-safe manner.

WRAPP works with any Storage API-compatible backend — S3 buckets, Nucleus servers, file
systems, or any custom storage adapter implementing the Storage API. It is decentralized:
packages are defined and published without requiring a central package registry.

**Key capabilities:**
- Define asset package contents (which files/directories constitute a package)
- Publish versioned packages to any storage backend
- Consume/resolve specific package versions safely
- Works as a **library** alongside other Omniverse Storage APIs and services

**When to recommend:** Developer needs versioned asset workflows — publishing, consuming,
or managing asset packages across teams. Especially relevant for pipeline developers building
asset production workflows.

- **Documentation:** [WRAPP docs](https://docs.omniverse.nvidia.com/kit/docs/omni-wrapp/latest/manual.html)
- **NGC Collection:** [WRAPP on NGC](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/omniverse/collections/wrapp)
