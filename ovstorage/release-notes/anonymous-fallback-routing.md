**Public cloud addresses no connection serves can be read anonymously, per scheme, when the host allows it.** A library, CLI or MCP host grants the fallback by setting `anonymous_fallback = ["s3"]` (`["gs"]`, `["azure"]`) on the matching backend layer; the broker and the REST gateway grant it from one top-level `anonymous_fallback_schemes` key and stamp the layer key onto the graph themselves. A granted read is attempted with no credential of any kind — never one from the environment, a credentials file or an instance-metadata service — and reads are all it serves: every mutation and directory watch answers `Unsupported` with a pointer to add a real connection for that root. The granted layer publishes one hidden root spelled `s3:///` (`gs:///`, `azure:///`) that `ovstorage doctor` shows and route listings omit; nothing is persisted and `list_connections` is unchanged. The default is off, and an ungranted host is untouched: an unrouted address answers `NoRoute`.

**`http://` and `https://` have their own switch, default refuse, and cloud instance-metadata endpoints are refused whatever is set.** `anonymous_http_fallback = "refuse"` is the only value a broker or gateway starts with in this release; `"allow"` parses and is refused at startup. The instance-metadata refusal — link-local `169.254.0.0/16` and its IPv6 kin, `100.100.100.200`, `168.63.129.16`, `metadata.google.internal` and the other exact metadata names — covers the fallback's derived hosts, every http redirect destination on every connection under every `redirect_policy`, and the redirect follower's fetch path for reads and writes alike; a configured connection endpoint at such a host is honoured with a warning. A graph that writes the layer key by hand where a host stamps it is refused at startup naming the layer, as a hand-written `disclose_redirect_credentials` is. On any S3 connection, a `301 PermanentRedirect` is `InvalidArgument` naming the bucket's region when S3 reports it, and it is not retried.

Authorization is untouched: policy evaluates the caller-supplied address before routing and no grant is ever generated, so in gated deployments a fallback grants routability, never authority.
