**Hugging Face Hub URLs resolve automatically for `huggingface` connections.**
When a `huggingface` connection registers below an `alias` layer, hidden alias rules for the Hub's own repository URL are generated from the connection's configuration — `https://huggingface.co/<namespace>/<name>/…` and its `http://`, `www.huggingface.co` and `hf.co` twins, prefixed `datasets/` or `spaces/` for those repository types, and exactly the configured shape for a loopback `endpoint`. A user pasting `https://huggingface.co/acme/demo/config.json?revision=main` gets the object without translating it to `hf://models/acme/demo/config.json?revision=main` first, and pinned `list` children and `versioned_address` values project back onto the caller's spelling. Generated rules are hidden (addressable, reported with `visible = false`), regenerate at registration rather than persisting, are withdrawn with their connection, and are marked with `org.omniverse.ovstorage/alias-derived-from` in `list_connections` output. The Hub's web-view and download URLs (`/blob/<rev>/`, `/resolve/<rev>/`, `/tree/<rev>/`, `?download=true`) are not unwrapped: the first three are read as in-repository paths at the connection's revision and normally answer `NotFound`, and `?download=true` makes the generated rule stand aside, so the address falls through to whatever else routes it (normally `NoRoute`). Authorization is untouched: policy evaluates the caller-supplied address before alias resolution and no grant is ever generated, so in gated deployments the generated aliases do nothing until their URL space is granted.

**`revision` joins the shared carried-query allowlist.** A generated alias rule and the anonymous scheme fallback carry `versionId`, `versionid`, `generation` and `revision` through to the backend and stand aside for any other query key, so a Hugging Face `?revision=` pin routes through a generated spelling. The cloud backends ignore a `?revision=` they do not read, exactly as they ignore each other's selectors; `revision` is not a parameter of any presigned-URL or SAS scheme, so the credential guard is unchanged.
